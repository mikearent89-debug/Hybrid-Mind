# Mapping to the Workbench data specification

Each memory record maps to a record in the EAM_MA DATA-SPEC v1.1 so milestone M4 can publish into the Workbench without translation. Field names follow the memory types; the DATA-SPEC column names the counterpart and section.

| Memory record | DATA-SPEC counterpart                                                                | Shared fields                                                                                                                                            | Differences to resolve in M4                                                                       |
| ------------- | ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| source        | Document (4.1), Communication source (6.8)                                           | id, title, type/kind, site associations, access policy                                                                                                   | Workbench has no `originSystem`; goes into the source registry (3.11)                              |
| revision      | Revision (4.1)                                                                       | document ID, integrity hash, import/received time, superseded status                                                                                     | Workbench `source_version` and `revision_label` are not kept here                                  |
| anchor        | Anchor (4.1)                                                                         | revision ID; page, region, text span, time segment                                                                                                       | `row` and `image-region` locators are additions                                                    |
| episode       | Import result / batch (9), audit event batch ID (3.11)                               | correlation ID, actor, time, method                                                                                                                      | —                                                                                                  |
| entity        | Site (3.2), Organization (3.3), Person (3.4), Equipment unit (3.5), Contract (6.1)   | `externalRefs.workbench` = Workbench record ID                                                                                                           | `firmware` has no Workbench record; add a firmware field to Equipment (3.5)                        |
| entity-alias  | Source mapping (3.11)                                                                | external name → internal ID                                                                                                                              | —                                                                                                  |
| claim         | Evidence link (4.2) with role; assertion-level `evidence_class` / `review_state` (2) | roles supporting / conflicting / contextual / superseding; effective window                                                                              | Workbench has no first-class claim record; publish as evidence links on the case                   |
| case          | Investigation (5.3) + Knowledge case (6.5)                                           | symptom, applicability, hypotheses, supporting/conflicting evidence, diagnostic actions, conclusions, unresolved questions, reviewer, limitations, owner | Cost and downtime publish as cost entries (6.6) only with a basis anchor                           |
| lesson        | Knowledge case (6.5)                                                                 | reviewed solution, applicability, limits, source evidence                                                                                                | Workbench has no lesson status; map candidate/reviewed → unreviewed/accepted, retired → superseded |
| candidate     | Extraction candidate (6.8)                                                           | source revision/anchor, proposed change, method/version, reviewer, decision/time, resulting canonical ID                                                 | —                                                                                                  |
| proposal      | Decision (6.5)                                                                       | question (the case), alternatives (assessment), evidence, selected action (draft), decision-maker, date                                                  | Two gates publish as two review provenance entries                                                 |
| outcome       | Decision outcome review (6.5)                                                        | later outcome review                                                                                                                                     | —                                                                                                  |

Common conventions shared verbatim: `id`, `record_version`, `evidence_class`, `review_state`, `reviewed_by`, `reviewed_at`, `effective_from`, `effective_to`, `access_scope` (DATA-SPEC section 2); append-only log with bitemporal times and positions as version boundaries (section 1a); principle 10 on uncertainty (section 1).
